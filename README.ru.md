# Конфигуратор блокировок и перенаправлений DNS

Настраивает правила перенаправления и блокировки сайтов для аккаунтов Cloudflare и NextDNS.

**Готов к запуску через GitHub Actions. Ничего скачивать и устанавливать не нужно.** [Видеоинструкция](https://www.youtube.com/watch?v=vbAXM_xAL5I)

## Сравнение бесплатных тарифов NextDNS и Cloudflare

|                                  | NextDNS                                                | Cloudflare                                                                                            |
|----------------------------------|--------------------------------------------------------|-------------------------------------------------------------------------------------------------------|
| **Лимит DNS-запросов**           | 300 000 в месяц                                        | 100 000 в день                                                                                        |
| **Ограничения IPv4**             | DNS-запросы ограничены одним IP-адресом, его можно менять | DNS-запросы строго ограничены одним IP-адресом, который Cloudflare назначает автоматически            |
| **DoH / DoT / IPv6**             | Без ограничений                                        | Без ограничений                                                                                       |
| **Ограничения настройки по API** | 60 запросов в минуту                                   | Без ограничений                                                                                       |
| **Общие ограничения**            | Отсутствуют                                            | Инфраструктура блокируется РКН, возможны проблемы с доступностью в РФ                                 |
| **Преимущества**                 | Встроенные опции блокировки рекламы и трекеров         | Более стабильная и быстрая инфраструктура                                                             |

Если пользователь находится в РФ, **NextDNS** является единственным практичным вариантом из этих двух из-за ограничений РКН.

В других странах **Cloudflare** предлагает более щедрые лимиты бесплатного тарифа. Блокировку рекламы и трекеров можно включить через список доменов в `BLOCK`, например: https://small.oisd.nl/domainswild2

## Простой способ настройки

Откройте конфигуратор https://dns-conf-ui.vercel.app и выберите режим **Quick**. Он автоматически настроит DNS-профиль и выполнит необходимые действия на GitHub.

Достаточно войти через GitHub и указать **CLIENT_ID** и **AUTH_SECRET**. Подробнее: [Настройка учетных данных](#настройка-учетных-данных).

## Настройка учетных данных

### NextDNS

1. Создайте **API-ключ** на странице https://my.nextdns.io/account и сохраните его в секрете окружения `AUTH_SECRET`.
2. Откройте https://my.nextdns.io, скопируйте ID из раздела **Endpoints** и сохраните его в секрете окружения `CLIENT_ID`.

### Cloudflare

1. Зарегистрируйтесь в **Cloudflare**, откройте вкладку _Zero Trust_ и создайте аккаунт.
   - Бесплатного тарифа достаточно для этого сценария.
   - Добавление платежного метода можно пропустить через _Cancel and exit_ в правом верхнем углу.
   - Вернитесь во вкладку _Zero Trust_.
2. Создайте **Cloudflare API token** на странице https://dash.cloudflare.com/profile/api-tokens со следующими разрешениями:

       Account.Zero Trust : Edit
       Account.Account Firewall Access Rules : Edit

   Сохраните токен в секрете окружения `AUTH_SECRET`.
3. Найдите **Account ID** на странице https://dash.cloudflare.com/?to=/:account/workers и сохраните его в секрете окружения `CLIENT_ID`.

## Настройка источников данных

Каждый источник должен быть ссылкой на hosts-файл, например:

https://raw.githubusercontent.com/Internet-Helper/GeoHideDNS/refs/heads/main/hosts/hosts

Несколько источников указываются через запятую:

`https://first.com/hosts,https://second.com/hosts`

### 1. Настройка перенаправлений

Укажите ссылки на источники в переменной окружения `REDIRECT`.

Скрипт игнорирует перенаправления на `0.0.0.0` и `127.0.0.1`. Например, из строк:

    0.0.0.0 domain.to.block
    1.2.3.4 domain.to.redirect
    127.0.0.1 another.to.block

для обработки редиректов будет использована только эта запись:

    1.2.3.4 domain.to.redirect

Приоритет редиректов соответствует порядку источников. Если домен встречается несколько раз, используется первый найденный IP-адрес.

### 2. Настройка блоклиста

Укажите ссылки на источники в переменной окружения `BLOCK`.

Скрипт оставляет записи, перенаправленные на `0.0.0.0`, `127.0.0.1` или `::1`, а также строки, содержащие только домен. Например, из строк:

    1.2.3.4 domain.to.redirect
    0.0.0.0 domain.to.block
    127.0.0.1 another.to.block
    ::1 ipv6.to.block
    no-ip.just.domain

для блокировки будут использованы:

    domain.to.block
    another.to.block
    ipv6.to.block
    no-ip.just.domain

- Для **Cloudflare** можно использовать один источник для `BLOCK` и `REDIRECT`.
- Для **NextDNS** практичный вариант: задать только `REDIRECT`, а списки блокировки выбрать вручную во вкладке _Privacy_.

## Настройка исключений редиректов (опционально)

Добавьте домены в переменную окружения `EXCLUDE_REDIRECT` через запятую без пробелов, например:

`instagram.com,twitch.com`

Эти домены и все их поддомены:

- будут удалены из существующих правил перенаправления;
- не будут добавляться в новые правила.

## Настройка нескольких профилей

### Ограничения

Все профили получают одинаковые значения `BLOCK`, `REDIRECT` и `EXCLUDE_REDIRECT`.

### Несколько профилей одного провайдера

Укажите значения профилей в соответствующих секретах и переменных окружения через запятую без пробелов. Пример для двух профилей NextDNS:

- `AUTH_SECRET`: `секрет_NextDns_1,секрет_NextDns_2`
- `CLIENT_ID`: `идентификатор_NextDns_1,идентификатор_NextDns_2`

### Несколько профилей разных провайдеров

Дополнительно перечислите провайдеров в переменной окружения `DNS`. Пример:

- `DNS`: `NEXTDNS,CLOUDFLARE,NEXTDNS`
- `AUTH_SECRET`: `секрет_NextDns_1,секрет_Cloudflare_1,секрет_NextDns_2`
- `CLIENT_ID`: `идентификатор_NextDns_1,идентификатор_Cloudflare_1,идентификатор_NextDns_2`

## Поведение скрипта

### Cloudflare

Ранее сгенерированные данные удаляются. Скрипт распознает их по следующим признакам:

- префиксы имен списков: **_Blocked websites by script_** и **_Override websites by script_**;
- префикс имени правила: **_Rules set by script_**;
- другой **_Session id_**, который хранится в поле description.

После удаления старых данных создаются и применяются новые списки и правила.

Чтобы очистить настройки блокировки или перенаправления Cloudflare, запустите скрипт без соответствующего источника. Например, пустое значение `BLOCK` удалит ранее созданные списки и правила блокировки.

### NextDNS

Для `REDIRECT`:

- существующий домен обновляется, если изменился IP-адрес перенаправления;
- новые домены добавляются;
- остальные настройки перенаправлений сохраняются.

Для `BLOCK`:

- новые домены добавляются;
- остальные настройки блокировки сохраняются.

Ранее сгенерированные данные удаляются только тогда, когда одновременно не заданы источники `BLOCK` и `REDIRECT`.

## Настройка GitHub Actions

### Видеоинструкция

[Настройка REDIRECT для NextDNS](https://www.youtube.com/watch?v=vbAXM_xAL5I)

### Шаги

1. Сделайте fork репозитория.
2. Откройте _Settings_ → _Environments_.
3. Создайте окружение с именем `DNS`.
4. Добавьте `AUTH_SECRET` и `CLIENT_ID` в **Environment secrets**.
5. Добавьте `DNS`, `REDIRECT`, `BLOCK` и `EXCLUDE_REDIRECT` в **Environment variables**.

Action запускается ежедневно в **01:30 UTC**. Чтобы изменить время, отредактируйте cron-выражение в `.github/workflows/github_action.yml`.

Для ручного запуска откройте вкладку _Actions_, выберите **DNS Block&Redirect Configurer cron task** и нажмите **Run workflow**.
